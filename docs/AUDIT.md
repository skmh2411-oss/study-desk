# 品質監査

開発担当とは別のQA担当エージェントが、実装コードと独自の自動テストを確認した。第三者認証・実機認証ではない。

## 検証結果

`npx vitest run tests/audit.test.ts`：独自の17件すべて成功。

`npx vitest run`：全4ファイル、43件すべて成功（独自監査17、基盤13、同期9、復習4）。同時点のTypeScriptチェックも成功。

- タイマーの同時開始・同時終了、保存の二重登録防止。
- 一時停止後のDB再接続・再開で停止時間を除外。
- 実際の計測区間を端末の現地日付の午前0時で分割。
- 古い編集画面の保存拒否と現在データの保持。
- 不正JSON・未対応スキーマ・不正な最終行の取り込み拒否。
- 同一ID競合・繰り返し取り込みで既存データを上書きしない。
- プレビュー後に不正内容へ変えた取り込みをコミット時に再検証。
- 不正なFSRS状態・解答を選べない問題の取り込み拒否。
- 同じカード版に対する重複採点の拒否。
- 日別の計画上限・学習不可日・不足時間・完了済み履歴の保護。
- プレビュー後にデータが変わった計画を適用しない。
- 模擬同期通信で、送信途中の端末編集をキューから消さない。
- 不正な受信データを保存前に拒否し、同期カーソルを進めない。
- 競合発生後に端末を再編集しても、再同期・明示選択で解決可能。

実通信を使わない同期テストはクライアントの安全性を確認するもので、Supabase上のRLS・SQLの実行成功を証明しない。

## 発見事項と修正

| 重要度 | 発見した問題 | 対応・確認 |
|---|---|---|
| P1 | FSRSの状態に小数を取り込める | 整数・状態範囲・難易度範囲を検証。独自テスト成功 |
| P1 | 解答を選べない問題データを取り込める | 重複しない2つ以上の選択肢と正解の所属を検証。独自テスト成功 |
| P1 | 競合後の追加編集で競合解決を進められない | 再同期時の端末版更新とトランザクション内再読込。独自テスト成功 |
| P1 | ノート保存失敗後の画面移動で下書きを失う可能性 | 各編集を即時に端末内の復元候補へ退避し、最新保存完了後のみ除去。コード確認、UI操作は統合検証対象 |
| P1 | 学習記録のメモ編集で一時停止区間が連続区間へ変わる | 日時・時間が同じ場合は既存区間を保持。時間を変える場合は明示確認。コード確認 |
| P1 | 秒単位計測の小数分が編集フォームの整数制約に抵触 | 編集欄を小数・1分未満に対応させ、保存時は正数を検証。コード確認 |
| P1 | ノート空タイトル・空本文からのカードがバックアップ復元条件を満たさない | 保存するタイトルの既定値を設定し、空本文からのカード作成を拒否。共通保存時にも形式検証。コード確認 |
| P1 | 科目編集中の学習対象切替・単元の科目移動で関連データの所属がずれる | フォーム表示中の対象切替、既存単元の所属科目変更を無効化。コード確認 |
| P1 | 別の学習対象で既に学習した時間を今日の計画余力に反映しない | 全対象の実績から日別余力を計算。変更後の古い計画案も拒否する回帰テストを追加 |
| P2 | 複数画面から異なる新規カードを採点すると1日上限超過 | 採点トランザクション内で紹介枚数を再検証。開発担当の並行実行テストあり |
| P2 | CSVの先頭空白後の数式を無効化できない | 空白・制御文字後の数式開始もアポストロフィで無効化。コード確認 |

同期のRLSはSQL上、`auth.uid()`により所有者を限定し、本人別の複合主キーと版比較によって更新する設計。任意HTMLはMarkdownで実行せず、外部画像も自動読込しない。ソースに秘密鍵や個人の実利用データは含めない。

## 検証の限界

- iPhone実機、Safariの終了・再開、OSによるストレージ解放は未検証。
- Supabaseの実プロジェクト、実メール認証、実際の別アカウント間RLS、実際の2端末同期は未検証。
- GitHub Pagesでの公開・ホーム画面への追加は本人設定後に検証が必要。
- 画面・PWAオフライン動作・本番ビルドは主担当の統合検証結果を参照。
- SafariのWebサイトデータ削除、端末故障、OSによる保存領域の整理まで端末内保存だけで保証することはできない。JSONバックアップが必要。

## 最終確認追記

上記の修正を最終コードで確認した。独立QAが確認した範囲で、既知のP0・P1は残っていない。自動テストが通ることと、iPhone実機・外部サービスの実動作が検証済みであることは区別する。

ブラウザの統合動作・PWAキャッシュ・画面幅・本番ビルドについては、主担当が取得する統合検証結果に従う。
