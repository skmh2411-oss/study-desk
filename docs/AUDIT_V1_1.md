# v1.1 選択共有・CSPの独立監査

開発担当とは別のQAエージェントが、新しいv1.1コピーのコード・自動テスト・生成HTMLを確認した。第三者認証や実機セキュリティ認証ではない。今回のQAによる変更は `tests/privacy-audit.test.ts` と本書のみ。

## 結果

- 独自の安全性テスト16件成功。
- 全6ファイル・61件の回帰テストとTypeScriptチェックの成功を実行確認。最終ビルド・ブラウザ検証は主担当の統合結果を参照。
- 確認した範囲で既知のP0・P1は残っていない。

## 確認内容

| 対象           | 実施した確認                                         | 結果                                                                    |
| -------------- | ---------------------------------------------------- | ----------------------------------------------------------------------- |
| 共有の初期状態 | IDを個別選択しない場合                               | 共有データは0件                                                         |
| 選択と範囲     | 選択外、削除済み、別対象、種別外、矛盾する階層条件   | ペイロードに含まれない                                                  |
| データ最小化   | レコードに認証値・独自拡張・同期情報のダミー値を追加 | 許可リストの学習項目だけを出力                                          |
| 時間・復習情報 | 正確な計測区間、開始・終了の数値、復習全履歴         | 共有しない。計測は日別分数に集計                                        |
| メモ・誤答原因 | 明示許可の有無を切り替え                             | 許可した場合だけ追加                                                    |
| 古い依頼文     | ID・階層・種別・追加条件・依頼・共有内容を変更       | 署名が変化し、以前の依頼文と区別可能                                    |
| コピー処理     | コンポーネントの実行処理をコード確認                 | 確認済み・最新の署名・空でない本文をコピー直前にも判定                  |
| 本番CSP        | 生成関数・Viteの本番HTML変換を実行                   | 外部JavaScript、inline JavaScript、evalを許可しない                     |
| 通信先         | 未設定と承認済みURLの両方を生成・検証                | 既定は同一オリジンのみ。設定時は本人の特定Supabaseオリジン1件だけを追加 |
| 旧同期設定     | 未承認の保存済みURL、SDK作成後に別URLへ変更          | SDK作成・認証呼出し前に拒否                                             |
| CSPの挿入順    | 本番HTML変換と生成済み `dist/index.html` を確認      | `<head>`直後で、script・linkより前                                      |

CSPには `object-src 'none'`、`frame-src 'none'`、`base-uri 'none'`、`form-action 'none'` を指定。KaTeXとReactの表示に必要なstyle属性は許可し、JavaScriptの許可とは分けている。開発サーバーではHMR用の緩和があるが、本番出力のCSPには入らない。外部参照元へのReferrerも抑止する。

## 検出事項

初回検査では、旧保存済みの未承認同期先を実行時に拒否する処理がまだ統合されていなかった。`validateSyncConfig` で承認済みオリジンとの一致を確認する修正後、未設定時とSDK初期化後の設定変更の両方をテストし成功した。


## 検証の範囲と限界

- 選択したノート本文・問題・解答などの文章は本人の選択どおりに含む。文章そのものに書かれた秘密情報を自動判定して除去する機能ではない。共有内容のプレビューと本人確認が必要。
- 署名差分と実行直前のガードは確認したが、本担当はブラウザ操作を行っていない。ボタン操作・クリップボード・ブラウザによるCSP拒否の実証は主担当の統合検証と区別する。
- meta CSPではHTTPヘッダー専用の `frame-ancestors` を設定できず、他サイトからこのアプリ自体を埋め込むことの防止までは保証しない。`frame-src 'none'` は、このアプリが外のフレームを開くことを制限する。
- CSPは信頼済みの同一オリジンの配信ソースやService Workerが改変された状況を解決するものではない。同一オリジンのスクリプトは許可される。
- Supabaseの実通信・実認証・実RLS、iPhone実機、GitHub Pages上での公開後の挙動は本担当では未検証。
